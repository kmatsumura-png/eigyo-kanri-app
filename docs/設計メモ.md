## 1. ファイル構成

```
eigyo-kanri-app/
├─ excel/                 ← 元の Excel を入れる場所（GitHubには上がらない）
├─ data/
│   ├─ dataset.json       ← Excel から作ったアプリ用データ（自動作成）
│   └─ edits.json         ← 画面で修正した内容
├─ scripts/import-excel.ts← Excel を読み込んで dataset.json を作るプログラム
├─ lib/                   ← 計算・判定のルール
│   ├─ config.ts          ← 対象メンバー・対象月・商品分類・色（★よく触る）
│   ├─ kpi.ts             ← KPI の計算方法
│   ├─ insights.ts        ← 自動コメント・課題判定のルール
│   ├─ parse.ts           ← 備考から商品・金額を読み取るルール
│   ├─ data.ts            ← データの読み込み・修正の保存
│   └─ types.ts           ← データの形
├─ app/                   ← 画面（1フォルダ＝1画面）
│   ├─ page.tsx           ← ① ダッシュボード
│   ├─ members/page.tsx   ← ② メンバー一覧（月別比較）
│   ├─ members/[id]/      ← ③ 個人詳細
│   ├─ deals/             ← ④ 案件一覧
```

## 3. 各KPIの取得元

| KPI | 7月・8月 | 9月 |
|---|---|---|
| 行動数（＝商談数） | 営業管理システム「月次実績」 | 営業管理システム「集計DB」 |
| GET数（＝契約数） | 〃 | 〃 |
| ポイント | 〃 | 〃 |
| 打電数・アポ数 | 営業管理システム「履歴ログ」の月末記録（行動・GET・ポイントが確定値と一致する、その月最後の記録） | 「集計DB」 |
| 接触数 | **元データなし**（「データなし」と表示） | 「集計DB」 |
| 契約案件・商品・契約金額 | 評価基準用数値集計「案件一覧」（営業担当が5人のどれかの行） | 同左 |
| 商談の明細 | トップチーム行動予定表 | 同左 |

### 見つかったデータ不一致（アプリの「データ確認」画面に表示）
- ポイント：営業管理システムと評価基準「総合ランキング」の有料商材ポイントが違う月がある
  （例：松村7月 240pt と 184pt。差の -56pt は案件一覧の過去案件のマイナス計上）。
  アプリは優先順位どおり営業管理システムの値を使います。
- GET数と案件一覧の契約行数が違う月がある（追加購入が別行になっているなど）。契約数は GET数 を使います。

## 4. データベースの構造

今回は「SQLite」などのデータベースソフトは使わず、**JSON ファイル**（メモ帳でも開ける文字のファイル）に保存しています。
初心者でも中身を確認でき、インストールで失敗しにくいためです。

- `data/dataset.json`
  - `kpis`：1人×1か月 の確定KPI（行動・GET・ポイント・打電・接触・アポ・出どころ）
  - `meetings`：商談1件ずつ（行動予定表の1行）
  - `contracts`：契約案件1件ずつ（案件一覧の1行。金額・金額状態・要確認の理由・注意点つき）
  - `issues`：データ不一致・要確認の一覧
  - `sourceFiles`：どのファイルを何に使ったか
- `data/edits.json`：契約案件ごとの手修正（契約金額・商品・管理者メモ・確認済み）

Excel を取り込み直しても `edits.json` は残り、自動で上書き反映されます。

## 6. 計算方法

- 商談数 ＝ 行動数、契約数 ＝ GET数
- 契約率 ＝ GET数 ÷ 行動数 × 100（小数1桁）。3か月は 3か月合計GET ÷ 3か月合計行動
- 契約金額 ＝ 案件一覧の備考の「→」の右側（最終販売価格）
- 平均単価 ＝ 契約金額合計 ÷ **金額が確定している契約の件数**
  （金額要確認の契約まで件数に入れると単価が実際より低く出てしまうため）
- 3か月平均 ＝ 3か月合計 ÷ 3（率だけは合計 ÷ 合計）
- 接触率 ＝ 接触 ÷ 打電、アポ率 ＝ アポ ÷ 打電、GET率 ＝ GET ÷ 行動（＝契約率）

### 金額要確認にするもの
金額の記載なし／セット商品（複数商品の合計金額）／月額・口座振替／金額が複数／
「値上げあり」なのに金額が下がっている等の食い違い／マイナス計上／過去案件の修正／
ポイントのないメモ行／重複の可能性。
読み取れた金額は「候補」として表示し、画面のボタン1つで確定できます。

### 課題の判定
5人のチーム平均と比べ、85%未満を「課題」、85〜100%を「やや低い」としています。
「アポ数 → 行動数 → 契約率 → 平均単価」の順に見て、最初に引っかかった所を一番の課題とします。
基準を変えたいときは `lib/insights.ts` の `ISSUE_LINE` を変えます。
